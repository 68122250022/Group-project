# 3.1 การวิเคราะห์ปัญหา
  Input: กล่อง n ใบ, Stack k กอง, และ ID กล่องเป้าหมาย
  
  Output: ลำดับการย้ายกล่อง, สถานะ Stack สุดท้าย
  
  ข้อจำกัด: ย้ายได้แค่กล่องบนสุด, ปลายทางต้องว่าง, ย้ายไปพักต้องเอามาคืน
  
  Assumptions: ID กล่องไม่ซ้ำกัน
  
  กรณีปกติ: เป้าหมายอยู่ตรงกลาง มีที่ว่างพอให้ย้ายกล่องขวางไปพัก
  
  กรณีขอบเขต: (ดีสุด) เป้าหมายอยู่บนสุด / (แย่สุด) เป้าหมายอยู่ล่างสุด ที่พักแทบไม่พอ
  
  กรณี Error: หาเป้าหมายไม่เจอ หรือ Stack ปลายทางเต็มหมด (Deadlock)
  
  Operation บ่อย: push(), pop(), peek()
  
  Operation นานสุด: การสแกนหาเป้าหมาย และ วนลูปหา Stack ว่าง

# 3.4 การแสดงตัวอย่างแบบ Step-by-step

1. กรณีปกติ (Normal Case - ทดสอบด้วย Best Fit):
   
  สถานะเริ่มต้น: Target = กล่อง B
  
    Stack 1 (Cap 3): [Top: C, B, A :Bottom]
    
    Stack 2 (Cap 3): [Top: D :Bottom] (ว่าง 2 ช่อง)
    
    Stack 3 (Cap 3): [ Empty ] (ว่าง 3 ช่อง)

  Step 1: Pop C ออกจาก Stack 1. เปรียบเทียบพื้นที่ว่าง (Stack 2 เหลือ 2 ช่อง, Stack 3 เหลือ 3 ช่อง) -> เลือก Stack 2. Push C ลง Stack 2
  	
    Stack 1: [B, A] | Stack 2: [C, D] | Stack 3: [ Empty ] 

  Step 2: Top ของ Stack 1 คือ B (เป้าหมาย) -> Pop B ออกสำเร็จ
  	
    Stack 1: [A] | Stack 2: [C, D] | Stack 3: [ Empty ]

  Step 3: ย้าย C จาก Stack 2 กลับมาคืน Stack 1
    
    สถานะสุดท้าย: Stack 1: [C, A] | Stack 2: [D] | Stack 3: [ Empty ]

2. กรณีขอบเขต / เลวร้ายที่สุด (Boundary/Worst Case):
   
  สถานะเริ่มต้น: Target = กล่อง A (อยู่ล่างสุด)
  
  	Stack 1 (Cap 3): [Top: C, B, A :Bottom]
    
    Stack 2 (Cap 2): [Top: D :Bottom] (ว่าง 1 ช่อง)
    
    Stack 3 (Cap 2): [Top: E :Bottom] (ว่าง 1 ช่อง)
    
  Step 1: Pop C ออกจาก Stack 1 -> ย้ายไป Stack 2 (เหลือว่าง 0 ช่อง)
    
    Stack 1: [B, A] | Stack 2: [C, D] | Stack 3: [E] 

  Step 2: Pop B ออกจาก Stack 1 -> ย้ายไป Stack 3 (เหลือว่าง 0 ช่อง)
  
  	Stack 1: [A] | Stack 2: [C, D] | Stack 3: [B, E] 

  Step 3: Pop A ออกจาก Stack 1 (นำเป้าหมายออกสำเร็จ) 

	  Stack 1: [ Empty ] | Stack 2: [C, D] | Stack 3: [B, E] 

  Step 4: ย้าย B จาก Stack 3 คืน Stack 1 แล้วย้าย C จาก Stack 2 คืน Stack 1
  
    สถานะสุดท้าย: Stack 1: [C, B] | Stack 2: [D] | Stack 3: [E]


# 3.5 การอธิบายความถูกต้อง (Correctness Proof Using Loop Invariant)

เลือกลูปในขั้นตอนการดึงกล่องที่ขวางออก (WHILE loop):

  1. สภาพก่อนเริ่ม (Precondition): ข้อมูลกล่องทุกใบอยู่ใน Stack อย่างถูกต้อง กล่องเป้าหมายอยู่ใน Stack ต้นทาง ณ ตำแหน่งที่มีกล่องขวางอยู่เหนือมันเป็นจำนวน h ใบ
  
  2. คุณสมบัติระหว่างทำงาน (Loop Invariant): ในการทำงานรอบที่ i กล่องขวางบนสุดจะถูกย้ายไปพักที่ Stack ปลายทางที่มีพื้นที่ว่างอย่างถูกต้อง ทำให้จำนวนกล่องที่ขวางอยู่เหนือเป้าหมายใน Stack ต้นทางลดลงเหลือ h-i ใบ โดยไม่มีกล่องใดสูญหายไปจากระบบ
 
  3. เมื่อหยุดทำงาน (Postcondition / Termination): ลูปหยุดทำงานเมื่อกล่องบนสุดของ Stack ต้นทางคือกล่องเป้าหมาย (h-i=0) การสั่ง pop() ถัดไปจึงได้กล่องเป้าหมายตามเงื่อนไขถูกต้อง
 
  4. ความสมบูรณ์ของข้อมูล (Data Integrity): กล่องที่ไม่เกี่ยวข้องซึ่งถูกย้ายไปพักชั่วคราวใน tempMoved จะถูก push() กลับคืนสู่ Stack ต้นทางตามลำดับ ทำให้ลำดับกล่องที่เหลือคงเดิมและไม่สูญหาย
  
  5. การหยุดทำงาน (Halting): เนื่องจากจำนวนกล่อง h เป็นจำนวนจริงบวกที่มีค่าจำกัด และลดลงรอบละ 1 ใบเสมอ อัลกอริทึมจึงต้องทำงานจบตามจำนวนรอบ h แน่นอน ไม่เกิด Infinite Loop

3. การอภิปรายผลการทดลอง

  ความสอดคล้องกับ Big-O: จากตารางพบว่า เมื่อขนาดข้อมูล n เพิ่มขึ้น เวลาในการประมวลผล (Average Time) ของทั้งสองอัลกอริทึมจะเพิ่มขึ้นในลักษณะแปรผันตรง (Linear Growth) ซึ่งสอดคล้องกับการวิเคราะห์ Worst-case Time Complexity ที่ O(n + h * k)

  เปรียบเทียบประสิทธิภาพ A vs B: Algorithm B (Best Fit) ใช้เวลาในการทำงานมากกว่า Algorithm A ชัดเจน สาเหตุหลักมาจาก "จำนวนการเปรียบเทียบ (Comparisons)" ของวิธี B ที่พุ่งสูงกว่าวิธี A ถึงประมาณ 2.5 เท่า เนื่องจากวิธี B ถูกบังคับให้วนลูปสแกนตรวจพื้นที่ว่างครบทุก Stack เสมอ ในขณะที่วิธี A ใช้หลักการ Early Exit จึงหลุดจากลูปได้ทันทีเมื่อพบพื้นที่ว่างแรก
